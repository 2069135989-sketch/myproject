# 债券一级统计界面 — 接口需求文档

> 来源：onshore-bond-primary（C:\onshore-bond-primary）
> 用途：练习项目手敲复刻。参考控制器：
> - `BondPrimaryStatsController`（V1，api/bond/stats）
> - `BondPrimaryStatsV2Controller`（V2，api/bond/primary/stats/v2）
>
> 注：`controller/internal/` 下的同名 Controller 是服务间内部接口，不属于统计界面，本文档不涉及。

---

## 1. 全局约定

| 项 | 约定 |
|---|---|
| 请求方式 | 全部 `GET`，参数走 query string（DTO 绑定） |
| 统一响应 | `RestResponse<T>`（com.innodealing.commons.http）：`{code, message, data}`，成功用 `RestResponse.Success(data)` |
| 用户标识 | 从 Cookie `userid` 取（`@CookieValue(name="userid", required=false) Long userId`），塞进 DTO 的隐藏字段 `userId`，用于"关注组"等个性化过滤 |
| 分页响应 | `NormPagingResult<T>`（mybatis-dynamic-query 提供）：`{data, total, pageNum, pageSize}` |
| 排序参数 | `propertyName`（排序字段，默认 `actualIssueAmount`）+ `sortDirection`（`ASC`/`DESC`，默认 `DESC`），排序方向必须双向支持（前端可切换升降序，后端不得硬编码 DESC） |
| 导出接口 | 无返回值，直接往 `HttpServletResponse` 写 Excel 流（EasyExcel），produces `application/octet-stream` |
| 金额单位 | 亿元；利差单位 BP |

## 4. 数据口径要点（写 SQL 时注意）

1. **dateType 决定统计日期列**：同一批债券，缴款日口径和上市日口径下的发行金额分布完全不同，所有接口都基于所选口径过滤。
2. **金额三剑客**：发行金额（实际发行）、到期金额、净融资额 = 发行 - 到期；延迟/取消金额单独统计不进正数口径。
3. **地区编码 -1 的语义**：表示"其他"聚合值，SQL 需同时匹配 0 和 NULL；0 传参是无效值直接忽略。
4. **行业口径双轨**：industryStandard=1 走申万列，=2 走 DM 行业列，筛选和分组必须用同一列。
5. **期限档位左开右闭**：tenorTags 与自定义 startTenor/endTenor 组合时注意边界。
6. **增发/续发**：issueNum=0 为原债，>0 为增发/续发；明细里同一 bondUniCode 可有多条 bondIssueId。
7. **排序**：所有列表类接口的 propertyName/sortDirection 由前端传入，后端需支持升序和降序两个方向，默认 DESC。

## 5. 建议实现顺序（练习路线）

1. 先搭框架：RestResponse、两个 Controller 空壳、请求/响应 DTO 全量字段。
2. 明细接口 (11)：单表查询 + 筛选条件拼装 + 分页排序，最练基本功。
3. 分组统计 (1)-(6)：GROUP BY + 聚合函数 + 动态排序。
4. 时间分组 (9)：日期归一（周/月/季/年）+ 空档补零。
5. 导出 (7)(8)(14)：EasyExcel 流式导出。
6. 利率走势 (12)(13)：分组系列数据组装。
7. V1 五个接口：字段聚合方式不同（横向铺开 vs 纵向列表），可对比体会两种响应结构设计。
